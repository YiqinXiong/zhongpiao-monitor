## 1. 先搞清楚：你的监控目标是什么状态

京东E卡在商城里有三种状态，我们的监控都能覆盖：

| 状态 | 界面表现 | 监控能否发现 | 能否下单 |
| --- | --- | --- | --- |
| 在架有货 | 显示"立即购买" | ✅ 立即提醒 | ✅ |
| 在架缺货 | 显示"补货中" | ✅ 有货瞬间提醒 | ❌ |
| **下架** | 商品消失/提示"暂时无法购买" | ✅ 重新上架瞬间提醒 | ❌ |

> 📌 **库存监控与城市无关**（2026-10-19 实测确认）：同一商品在深圳/北京查到的库存一致，
> 在深圳完全可以监控京东E卡。此前一次测试搜不到，是因为当时商品恰好都没上架。
>
> 📌 **默认已配好 4 个监控目标**（2026-10-19 实测均为"补货中"状态，有货即提醒）：
>
> | 商品 | skuId | 售价 |
> | --- | --- | --- |
> | 【京东E卡】100面值 | 12325240480893951 | 132 |
> | 【盒马鲜生】100面值 | 12325252256074751 | 132 |
> | 【中石化】面值100元加油电子兑换券 | 14598 | 129 |
> | 【三网通】100元话费充值 | 14794 | 129 |
>
> ⚠️ **每品种每天限量 1 张**：某个 sku 当天买成功后，程序自动停止监控/购买该 sku，**次日自动恢复**，不会重复抢购。

## 第一步：安装运行环境（约5分钟）

### 1.1 检查有没有 Python

**Windows**：按 `Win + R`，输入 `cmd` 回车，输入：

```bash
python --version
```

**Mac / Linux**：打开"终端"，输入：

```bash
python3 --version
```

- 显示 `Python 3.9` 或更高 → ✅ 已就绪，去 1.3
- 显示"不是内部或外部命令" → 去 1.2 安装
- 版本是 3.8 或更低 → 也去 1.2 装新的

### 1.2 安装 Python（只有没装才需要）

- **Windows**：打开 https://www.python.org/downloads/ ，下载最新版，安装时**务必勾选 "Add Python to PATH"**（第一步界面底部那个复选框），然后一路下一步。
- **Mac**：App Store 搜索安装 "Python" 或访问 https://www.python.org/downloads/ 下载安装包。
- **Linux（Debian/Ubuntu）**：`sudo apt update && sudo apt install python3 python3-pip python3-venv`

装完重新打开终端，再执行一次 1.1 的检查命令确认成功。

### 1.3 放置程序文件

把 `zpmon` 整个文件夹复制到电脑上，记住位置。比如：

- Windows：`C:\Users\你的用户名\Desktop\zpmon`
- Mac：`/Users/你的用户名/zpmon`

然后进入这个文件夹：

```bash
# Windows（把路径换成你的实际路径）
cd C:\Users\你的用户名\Desktop\zpmon

# Mac / Linux
cd ~/Desktop/zpmon
```

### 1.4 创建虚拟环境并安装依赖

```bash
# Windows
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# Mac / Linux
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

看到 `Successfully installed ...` 即成功。
（虚拟环境是给这个程序单独隔一间"小屋"，不污染你电脑的其他软件，每次用前都要先 `activate`。）

### 1.5 创建配置文件

```bash
# Windows
copy config.example.json config.json

# Mac / Linux
cp config.example.json config.json
```

至此环境就绪。✅

## 第二步：设置消息提醒（约5分钟）

### 2.1 关于"发消息到微信群"

**直接说结论：个人微信群没有办法免费、稳定、优雅地自动发消息。**

- 微信群没有对外开放机器人接口，网上那些"微信机器人"都是模拟登录，**有较大概率被微信封号**，不建议用来绑你自己的常用微信；
- 你想要的效果（补货了立刻知道），用下面任意一种方式都能实现，体验并不差。

三个可选方案，按推荐排序：

| 方案 | 到达哪里 | 费用 | 速度 | 适合谁 |
| --- | --- | --- | --- | --- |
| **① Bark** | iPhone 通知栏（可开警报声/弹窗强提醒） | 完全免费无限制 | 秒级 | iPhone 用户 ⭐ 推荐 |
| **② PushPlus** | 个人微信（服务号消息） | 免费（每天约200条） | 秒级 | 想在微信里收到的人 |
| **③ 企业微信机器人** | 企业微信群（微信里也能收到提醒） | 免费 | 秒级 | 有/愿意注册企业微信的人 |

**最稳组合：Bark 为主 + PushPlus 为备**，双路并发，任何一路挂了另一路照样叫你。

### 2.2 方案①：Bark 设置（iPhone，3分钟）

1. App Store 搜索 **Bark**，安装打开；
2. 首页会显示一串类似 `https://api.day.app/AbCd1234xyz/` 的地址，**最后那一段就是你的 Key**（例如 `AbCd1234xyz`），复制它；
3. 用记事本/vs code 打开 `config.json`，找到 `notify.bark`，把 key 填进去：

```json
"bark": {
  "url": "https://api.day.app",
  "key": "AbCd1234xyz"
}
```

4. 保存。完成。以后补货提醒就会以 iPhone 推送形式到达，锁屏也能看到。

### 2.3 方案②：PushPlus 设置（推到个人微信，2分钟）

1. 微信扫码打开 https://www.pushplus.plus/ ，登录；
2. 网页上方能看到你的 **token**（一长串字符），复制；
3. 填入 `config.json`：

```json
"pushplus": { "token": "你复制到的token" }
```

### 2.4 方案③：企业微信机器人（推到微信群，5分钟）

1. 手机或电脑打开企业微信（没有的话用微信就能注册，免费）；
2. 进入一个内部群聊 → 右上角设置 → **群机器人** → 添加 → 复制 **Webhook 地址**；
3. 填入 `config.json`：

```json
"wecom": { "webhook": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxx" }
```

> 以上三种**可以同时填多个**，程序会同时发送，哪路快用哪路。

### 2.5 验证提醒能到达（重要）

程序启动后，一旦检测到"缺货→有货"跳变就会推送。为了确认链路 OK，可以临时加一个有货商品测试（京东plus年卡深圳就有货）：

用记事本打开 `config.json`，在 `targets` 数组里临时加一项（注意逗号）：

```json
{
  "mode": "sku",
  "skuId": "29579",
  "name": "【京东】plus会员年卡"
}
```

启动监控（见第四步），**约 10 秒内你应该收到一条"补货提醒"推送**（因为plus年卡一直有货，启动即触发首次提醒）。
收到后把这项删掉即可。

> 💡 没收到？检查：key/token 是否填对、JSON 逗号/括号是否完整、Bark App 是否允许通知。程序运行窗口里也会打印 `[NOTIFY] xxx 发送成功/失败`，失败会写明原因。

## 第三步：配置要监控和购买的商品（约3分钟）

### 3.1 用工具查找商品 ID

程序自带查询工具。激活虚拟环境后执行：

```bash
# 查北京有哪些京东商品（E卡在北京的监控范围）
python find_product.py 京东 --city 110100

# 查深圳
python find_product.py 京东 --city 440300
```

输出会列出每个商品的 `productId`、`skuId`、库存、售价，并**直接生成一段可以粘贴的配置**。

### 3.2 三种监控模式怎么选

打开 `config.json` 的 `targets` 数组，每项是一个监控目标：

```json
"targets": [
  {
    "mode": "sku",
    "skuId": "12325240480893951",
    "name": "【京东E卡】100面值"
  },
  {
    "mode": "sku",
    "skuId": "12325252256074751",
    "name": "【盒马鲜生】100面值"
  }
]
```

| 模式 | 填什么 | 作用 | 建议 |
| --- | --- | --- | --- |
| `sku` | `skuId` | 盯住这一个商品，有货就提醒 | ⭐ 主力，最稳健 |
| `search` | `searchKey` + `nameFilter` | 按关键词搜索，发现**新上架/新规格** | 辅助；嫌打扰可删除 |
| `detail` | `productId` | 商品详情（信息最全） | 可选，与 sku 二选一 |

**默认配置已包含 4 个目标**（京东E卡/盒马/中石化/三网通，见第 1 节），开箱即用。
想改监控对象就改 `skuId`（用 3.1 的工具查出来）；想同时监控多个商品，多加几项、逗号隔开。

> 库存监控与城市无关，目标里不需要设置 `cityCode`。

### 3.3 每日限购 1 张：买中后当天自动安静

每个品种每天限量 1 张。程序的处理：

- **自动下单成功后**：该 sku 当天自动停止监控和购买，日志记录
  `[限购] sku=xxx 今日已购买，当天停止监控/购买该品种（次日自动恢复）`，**次日 0 点自动恢复**；
- **你自己手动买中了**：跑一次下面的命令让监控当天安静（监控运行时执行，下一轮即生效）：

```bash
python monitor.py --mark-purchased 14598     # 14598 换成你买中的 skuId
```

- **想当天重新监控某个品种**（测试或特殊情况）：

```bash
python monitor.py --reset-purchased          # 清除全部已购标记
```

### 3.4 商品 ID 自动校准（应对频繁上架下架）

商品经常上架/下架，**重新上架后可能分配新的 skuId**——固定 ID 会漏监控。程序的应对：

- 对配置了 `"calibrate": true` 的目标（默认 4 个品种都已开启），程序会：
  - **启动时**立即按 `searchKey` 搜索校准一次；
  - **每 24 小时**（`calibrateIntervalHours` 可调）自动校准一次；
  - 监控接口报错（ID 可能失效）时**立即**重搜校准；
- 校准时按**商品名**匹配搜索结果，发现 ID 变化就自动换成新 ID，并推送一条
  「监控目标已自动校准」通知（旧 ID → 新 ID）；
- 校准结果存在 `monitor_state.json`，重启不丢；商品搜不到时（下架中）保留原 ID 继续监控；
- 自动下单目标按**商品名**匹配，监控端换了新 ID 也不影响自动购买；
- 想手动立即校准：`python monitor.py --calibrate-now`。

## 第四步：启动监控（约1分钟）

```bash
# 先激活虚拟环境（每次新开终端都要做）
# Windows: .venv\Scripts\activate
# Mac/Linux: source .venv/bin/activate

python monitor.py
```

看到类似输出就是成功了：

```text
2026-10-21 11:00:00 监控启动 cityCode=440300 目标=5 基础间隔=120.0s 每日预算=3000 autoOrder=off
2026-10-21 11:00:00 [调度] 生效检查间隔 ≈ 120s/目标（今日已用 4/3000 次请求）
2026-10-21 11:00:00 [sku:12325240480893951] 缺货/补货中
```

### 4.1 频率与限流（重要，必读）

商城对**同一出口 IP 有每日访问配额**，超了会返回
`IP[x.x.x.x]今日访问频繁`，当天再发请求也会被拒。程序为此做了三层保护：

| 机制 | 说明 |
| --- | --- |
| **串行调度** | 每轮最多发 1 个请求，按各目标的 `minIntervalSec` 轮转。默认 120s/目标 → 4 个商品约 2880 次/天 |
| **每日预算** | `dailyRequestBudget`（默认 3000）内自动分配间隔，越接近预算间隔越长，**永远不会超预算** |
| **限流退避** | 一旦触发限流：立即暂停 30 分钟 + 间隔自动放慢（×2，最多 ×16）+ 推送通知；反复触发则暂停到次日 0 点 |

常用调整：

```jsonc
{
  "minIntervalSec": 120,          // 每个目标默认最小检查间隔（秒）
  "dailyRequestBudget": 3000,     // 每日请求预算；0 = 不限制（不推荐）
  "rateLimitBackoffMinutes": 30   // 触发限流后暂停多少分钟
}
```

- 单个目标可用 `minIntervalSec` 单独覆盖（示例配置里"发现新品"的搜索目标设为 600 秒）
- **想更快发现补货**：把 `minIntervalSec` 调小，同时把 `dailyRequestBudget` 一起调大（两者必须匹配，否则自适应会自动拉长间隔）
- 查看今日用量与限流状态：

```bash
python monitor.py --stats
```

> ⚠️ **换 IP 能立刻解封**：限流是按出口 IP 计的。急用时用手机热点/其他出口 IP，次日 0 点配额自动重置。


2026-10-17 12:20:17 监控启动 cityCode=440300 interval=10.0s targets=3 autoOrder=off
2026-10-17 12:20:17 [sku:12325240480893951] 缺货/补货中
```

- 每 10 秒自动查一次库存（带随机抖动，避免太规律被风控）
- 检测到有货 → **所有你配置的渠道同时推送**
- 窗口不要关；按 `Ctrl + C` 停止
- 详细日志在文件夹里的 `monitor.log`

## 第五步：自动下单的开启与关闭

> ⚠️ 自动下单会**真实扣除你的福利卡点数**，请务必先把"演练模式"跑通再开启。

### 5.1 先准备工作：登录态 + 下单参数

自动下单需要你的登录令牌（监控不需要，下单需要）：

**方式 A（推荐，半自动）**：安装 Playwright 并跑登录助手，在自动弹出的浏览器里手动完成短信登录，token 自动保存：

```bash
pip install playwright
playwright install chromium
python login_helper.py --phone 你的手机号
```

**方式 B（手动）**：Edge 登录商城后按 F12 → Console，执行 `localStorage.getItem('apiToken')`，复制结果。

**方式 C（NAS/无显示器环境，无需浏览器）**：用自带的终端登录工具，输手机号+短信验证码即可，
token 自动写入配置：

```bash
python login.py                    # 本机运行
docker exec -it zpmon python /app/login.py   # NAS 容器内运行
```

三种方式拿到的 token 填到（或自动写入）`config.json` 的 `"apiToken"` 字段。

然后填好下单参数（`autoOrder` 段）。**支持多个品种，每个品种配自己的充值账号**：

```json
"autoOrder": {
  "enabled": false,
  "dryRun": true,
  "targets": [
    { "skuId": "12325240480893951", "rechargePhone": "京东账号手机号", "quantity": 1, "maxWxPayAmount": 0 },
    { "skuId": "12325252256074751", "rechargePhone": "盒马账号手机号" },
    { "skuId": "14598", "rechargePhone": "中石化充值手机号" },
    { "skuId": "14794", "rechargePhone": "话费充值手机号" }
  ],
  "cardNos": []
}
```

| 参数 | 说明 |
| --- | --- |
| `targets` | **买哪些商品**：每项一个 skuId。只买这里列出的，搜索模式发现的其他商品**不会误买** |
| `rechargePhone`（每项内） | 该品种的充值账号：E卡填京东手机号、盒马填盒马账号、话费填充值手机号（**填错基本追不回，仔细核对**） |
| `quantity`（每项内） | 该品种购买数量，默认 1 |
| `maxWxPayAmount`（每项内） | 允许的微信补付上限（点数不够时防止误扣现金），0 = 不允许补付 |
| `cardNos` | 指定用哪张福利卡，留空 = 自动使用全部有余额的点数卡 |
| `matchName` | 备选：按商品名正则匹配购买目标（与 targets 二选一） |

> 只想自动买某一个品种？`targets` 里只留那一项即可。

### 5.2 演练模式（dryRun）——不扣款，先试跑

默认 `"dryRun": true`。这个状态下，补货被发现时程序会自动走到"订单预览"并停下，同时给你推送一条 **【演练】自动下单预览完成（未扣款）** 的消息，里面有点数抵扣、微信补付、备注手机号等你核对。

**确认预览数字没问题后，再进入下一步。**

### 5.3 开启真实自动下单

编辑 `config.json`：

```json
"autoOrder": {
  "enabled": true,
  "dryRun": false
}
```

保存后**重启监控**（`Ctrl+C` 停止再 `python monitor.py`；服务器上 `sudo systemctl restart zpmon`）。

启动日志会显示：`自动下单已开启（真实下单）目标: 12325240480893951,12325252256074751,...`

### 5.4 关闭自动下单

两种方式任选：

**方式一：改配置（永久生效）**——把 `enabled` 改回 `false`，重启监控。

**方式二：环境变量（适合临时切换，不用改文件）**——重启时带上环境变量：

```bash
# 关闭自动下单（只提醒）
ZPMON_AUTO_ORDER=0 python monitor.py

# 只开演练（下了单也不扣款）
ZPMON_DRY_RUN=1 python monitor.py

# 快捷真实下单（确认过配置后）
ZPMON_AUTO_ORDER=1 ZPMON_DRY_RUN=0 python monitor.py
```

> 环境变量优先级高于配置文件，改完都要重启进程才生效。

### 5.5 下单成功后会有哪些通知

| 场景 | 推送内容 |
| --- | --- |
| ✅ 下单成功 | **「自动下单成功！」+ 订单号 + 补付金额**，提醒你去"我的订单"查看 |
| ⚠️ 待微信支付 | 订单已创建但点数不够，提醒你**立刻手动支付**（超时关闭） |
| ❌ 提交前发现被抢空 | 「库存校验时已被抢空」，提醒手动刷新 |
| ❌ 加购失败/异常 | 具体错误信息，提醒立即手动下单 |
| 🧪 演练模式 | 【演练】预览完成，附全部预览数字供核对 |

**下单成功后，你也可以立刻手动去商城"我的订单"确认，并以实物为准。**

📌 **每日限购**：某个品种下单成功（或订单创建待支付）后，程序当天自动停止监控和购买该品种，日志出现 `[限购] sku=xxx 今日已购买`；**次日自动恢复**。手动买中后用 `python monitor.py --mark-purchased <skuId>` 让监控当天安静。

## 第六步（可选）：放到服务器 7×24 运行

> 🖧 **用群晖 NAS？** 直接看 [群晖NAS部署指南](群晖NAS部署指南.md)（Docker 一行部署，免装 Python），下面的 Linux 服务器步骤可跳过。

自己电脑合盖/断网就停了，想全天候监控就放 Linux 服务器。

```bash
# 1. 上传 zpmon 文件夹到服务器，例如 /opt/zpmon
# 2. 创建服务文件
sudo tee /etc/systemd/system/zpmon.service > /dev/null <<'EOF'
[Unit]
Description=zpmon restock monitor
After=network.target

[Service]
WorkingDirectory=/opt/zpmon
ExecStart=/opt/zpmon/.venv/bin/python monitor.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

# 3. 启动并设为开机自启
sudo systemctl enable --now zpmon

# 4. 查看实时日志
journalctl -u zpmon -f
```

改配置/开关自动下单后：`sudo systemctl restart zpmon`。

## 常见问题 FAQ

**Q1：监控需要一直登录着吗？**
不需要。查库存完全免登录；只有自动下单需要 token。token 失效只会影响自动下单，监控照常工作，失效后重新跑一次 `login_helper.py` 即可。

**Q2：验证码能全自动吗？**
不能，也不建议。验证码发到你本人手机，自动收码要么养一台安卓机做短信转发，要么用接码平台（违反平台协议且涉嫌违法）。人工登录一次，token 能用很久。

**Q3：多久轮询一次？会被限流吗？**
默认每 120 秒检查一个目标（4 个商品约 2880 次/天），并有每日预算（3000 次）自动兜底，**不会超配额**。
平台按出口 IP 计每日配额，超了会报「今日访问频繁」；程序会自动退避降速并通知你（见 4.1）。
另请注意：任何自动化都有违反平台用户协议的风险，请低调使用、不要多开、不要用于转售。

**Q4：商品显示"下架"了还能监控吗？**
能。这正是本方案的设计场景——商品下架时持续监控，重新上架且有货的瞬间就提醒你。

**Q5：监控和所在城市有关吗？**
无关。同一商品在哪个城市查到的库存一致（已实测），在深圳可以监控京东E卡。搜不到商品只说明它当时没上架，持续监控即可。

**Q6：132 元的售价怎么支付？点数够吗？**
预览接口会告诉你：点数抵扣多少 + 微信补付多少。你有约 1000+ 点数，够买多张；只要把 `maxWxPayAmount` 设为 0，点数不够时程序会拒绝下单而不会误扣现金。

**Q7：token 安全吗？**
token = 你的账号权限。不要发给别人、不要提交到 git、`config.json` 不要分享。建议 `chmod 600 config.json`。

**Q8：我想监控/自动购买多个商品？**
监控：在 `targets` 里加多项（默认已含 4 个品种）。自动购买：在 `autoOrder.targets` 里加多项，每项配自己的充值账号。两者独立控制，不会误买 targets 以外的商品。

**Q9：每个品种每天限量 1 张，程序会重复抢吗？**
不会。自动下单成功后该 sku 当天自动停止监控/购买，次日恢复；手动买中后跑 `python monitor.py --mark-purchased <skuId>` 即可让当天安静。

**Q10：商品重新上架后换了新 skuId 怎么办？**
程序每天自动校准：按关键词搜索、按商品名匹配，发现 ID 变化就自动更新并通知你（见 3.4）。也可以随时手动跑 `python monitor.py --calibrate-now`。

**Q11：接口变了怎么办？**
商城升级后如果监控全部报 API 错误，把新版本的接口抓包对比 `methodName` 和签名串，改 `zp_api.py` 顶部的 `APP_KEY` 即可（签名算法大概率不变）。

**Q12：这个方案合法吗？**
个人自用监控处于灰色地带，一般不违法，但违反平台用户协议的后果（限制登录、取消订单、冻结余额）需要自己承担。切勿用于批量抢购转售。详见《中票优品补货监控方案》第 8 章。
